# 레이어 3 & 4 · 제품 · 인터랙션 (프롬프트)

> 21 slide-decks(→ `slides`), 22 figma-mcp(앱에 Figma 커넥터 연결됨) 는 설치/연결됨.

## 19. hi-fi-mockups — 고해상도 UI 목업
```
<화면 이름>의 하이파이 목업을 만들어 줘.
- 실제 카피·실제 데이터 형태 사용 (lorem ipsum 금지)
- 디자인 토큰만 사용, 8px(또는 4px) 그리드
- 데스크톱 1440 / 모바일 375 두 버전
- 빈 상태, 로딩, 에러 상태 화면도 각각 1장씩
```

## 20. brandkit-sync — 재사용하는 브랜드 가이드
```
tokens.json과 assets/의 로고·폰트를 기준으로 brand.md를 만들고, 이후 모든 작업은 이 파일을 단일 기준으로 삼아.
토큰이 바뀌면 CSS 변수(tokens.css)와 tailwind 설정을 같이 갱신하고 변경 내역을 CHANGELOG에 한 줄 기록.
```

## 23. token-budgets — 컨텍스트 토큰 계산
```
작업 전에 참고 파일 목록과 대략적 크기를 보고 우선순위를 정해 줘.
- 꼭 읽을 것 / 필요할 때만 / 읽지 않을 것 으로 분류
- 큰 파일은 전체 대신 필요한 부분만(grep, 범위 지정) 읽기
- 긴 작업은 단계마다 진행 요약을 progress.md에 남겨 다음 세션이 이어받게
```

## 24. turn-repair — 끊어진 대화 흐름 복구 (챗 UI 설계)
```
이 대화형 UI에서 흐름이 끊기는 상황(오입력, 타임아웃, 맥락 이탈, 응답 실패)을 나열하고
각 상황마다 복구 화면/문구를 설계해 줘: 무엇이 잘못됐는지 → 사용자가 할 수 있는 다음 행동 1–2개 → 이전 맥락 유지.
```

## 25. generative-ui — 반응형 위젯 렌더링
```
응답 내용 유형(목록, 비교, 수치, 일정, 선택지)별로 텍스트 대신 렌더링할 위젯 컴포넌트를 설계해 줘.
각 위젯: 입력 데이터 스키마, 모바일/데스크톱 레이아웃, 로딩 스켈레톤, 데이터가 없을 때 대체 표시.
```

## 26. progressive-reveal — 단계별 정보 공개
```
이 화면의 정보를 3단계로 나눠 줘: 
1) 첫 화면에서 바로 보여야 할 핵심(결정에 필요한 것만)
2) 한 번의 상호작용(펼치기, 탭, 호버)으로 볼 것
3) 상세 페이지/모달로 보낼 것
각 단계의 트리거 UI와 전환 모션을 명시.
```

## 27. frustration-checks — 사용자 감정에 맞춘 대응
```
사용자 좌절 신호(반복 클릭, 같은 오류 3회, 뒤로가기 반복, 긴 체류 후 이탈)를 정의하고,
신호별로 UI가 어떻게 반응할지(도움말 노출, 단순 경로 제안, 사람 상담 연결) 설계해 줘. 탓하는 문구 금지.
```

## 28. feedback-loops — 수용된 인라인 수정 기록
```
내가 디자인 수정 요청을 하면, 반영 후 design-decisions.md에 
[날짜] 요청 / 변경 내용 / 이유 / 다른 화면에도 적용할 규칙 
형식으로 한 줄씩 기록하고, 다음 작업부터 이 규칙을 먼저 읽고 따라.
```
