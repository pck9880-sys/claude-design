# 레이어 6 · 신뢰 · 평가 (프롬프트)

백그라운드로 맡길 때 특히 중요한 항목들입니다. CLAUDE.md에 넣어 두면 매 세션 적용됩니다.

## 37. guardrails — 허용 범위를 벗어난 요청 차단
```
작업 범위: design-kit/ 안의 파일만 수정. 다음은 하지 말고 멈춘 뒤 보고:
- 범위 밖 파일 수정, 패키지 전역 설치, 외부 서비스에 게시/배포
- 브랜드 토큰(tokens.json) 임의 변경
- 요구사항에 없는 페이지 추가
```

## 38. trust-calibration — 인용·증거로 신뢰도 조정
```
디자인 결정마다 근거를 붙여: brief.md의 요구 / 레퍼런스 파일 / 스킬 규칙 / 내 판단 중 무엇인지.
"내 판단"으로만 정한 결정은 decisions.md에 따로 모아 내가 검토하게 해.
```

## 39. transparency-patterns — 답변의 확신 수준 추적
```
최종 보고에 확인 수준을 구분해서 써:
- 확인함(스크린샷/테스트로 검증)
- 추정함(코드상 맞지만 화면 확인 안 함)
- 못 함(이유)
```

## 40. quality-rubrics — 통과·실패 평가 기준표
```
완료 전 아래 기준표로 자가 평가하고 rubric-result.md에 저장. 하나라도 실패면 고치고 재평가.

```

## 41. task-decomposition — 목표를 에이전트 역할로 분해
```
이 작업을 독립 단계로 나눠 줘: 리서치 → 와이어프레임 → 시각 디자인 → 구현 → 검수.
각 단계마다 입력, 산출물 파일, 완료 기준을 적고, 서로 의존하지 않는 단계는 병렬 세션으로 돌릴 수 있게 표시.
```

## 42. handoff-protocols — 사람에게 전달할 문맥 파이프라인
```
작업이 끝나거나 막히면 HANDOFF.md를 남겨:
1) 한 일 / 남은 일
2) 내가 결정해야 할 것 (선택지와 추천)
3) 결과 파일 경로와 스크린샷
4) 다음 세션이 바로 이어갈 첫 명령
```
