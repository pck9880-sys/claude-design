# IR 덱 작업 절차

모든 단계의 결과는 파일로 남긴다. 다음 세션이 이어받을 수 있게.

## 1. 자료 수집
- 사용자가 파일명이나 키워드를 주면, 아래 폴더에서 찾는다 (읽기·탐색만 허용된 범위):
  `~/Documents`, `~/Downloads`, `~/Desktop`, `~/OneDrive` (있으면)
- 찾은 파일은 **복사**해서 `ir/inbox/`에 둔다. 원본은 절대 수정·이동·삭제하지 않는다.
- 후보가 여러 개면 수정일·파일명으로 고르고, 무엇을 골랐는지 보고한다.
- `python ir/scripts/extract_inbox.py` 실행 → `ir/inbox/_extracted/`

## 2. 니즈 조사서 정리
- `_extracted/`의 내용을 `ir/needs-survey.md` 양식으로 옮긴다.
- 원문에 없는 내용은 `<미확인>`. 추측 금지.
- 숫자는 `ir/data/*.csv`로 옮기고, 각 행에 출처(파일명·페이지)를 `source` 열로 적는다.
- "확인 질문"에 사용자에게 물을 것을 우선순위대로 적는다. 마감·숫자·민감 정보가 최우선.

## 2-1. 고객사 홈페이지·공개 정보 조사 (항상)
고객 자료와 별개로, 고객사 홈페이지와 공개 정보를 반드시 확인한다.
1. 홈페이지 주소: 고객 자료·명함·메일 서명에서 찾고, 없으면 회사명으로 웹 검색해 공식 사이트를 확인한다 (사칭·동명 회사 주의).
2. `python tools/site_scan.py <주소> --out output/ir-<작업명>/site` 실행
   → `site.md`(문구·숫자 후보·출처), `logo.*`/`og-image.*`, `colors.txt`
3. 수집된 페이지가 3개 이하이거나 본문이 거의 없으면(자바스크립트 사이트) Claude가 웹페이지 읽기로 회사소개·서비스 페이지를 직접 확인해 `site.md`에 보충한다.
4. 동시에 GPT에 외부 공개 정보를 맡긴다 (기다리지 말고 다음 단계 진행):
   `python tools/gpt.py research "<회사명> 투자 유치·수상·언론 보도·제휴 (최근 3년, 출처 링크 포함)" --out output/ir-<작업명>/site/press-gpt.md`
5. 결과를 `output/ir-<작업명>/site/check.md`로 정리한다:
   | 구분 | 내용 | 출처 URL | IR 사용 | 고객 확인 |
   |---|---|---|---|---|
   - **브랜드 색**: 색 후보 중 로고·대표 이미지와 실제로 일치하는 색을 골라 `tools/make_tokens.py --primary`로 작업별 토큰 생성 (고객 자료의 색이 있으면 그것이 우선)
   - **인용 문구**: 슬로건·미션·서비스 소개 중 IR에 쓸 만한 문장 (고객사 자신의 문구이므로 사용 가능, 문장 그대로·출처 표시)
   - **필요 자료**: 서비스 화면, 제품 사진, 파트너·고객사 로고, 수상·인증 내역 → 홈페이지에 있으면 위치를 적고 **원본 파일은 고객에게 요청** (홈페이지 이미지를 덱에 바로 쓰지 않는다)
   - **숫자 후보**: 사용자 수·거래액·파트너 수 등 → `ir/data`에 넣을 때 `source`에 URL을 적고, 기준일이 없거나 고객 자료와 다르면 확인 질문에 올린다
   - **불일치**: 홈페이지와 고객 자료가 다른 내용 (숫자·회사 설명·연혁)
6. `check.md`의 "고객 확인" 항목은 `needs-survey.md`의 확인 질문에 합친다.

## 3. 서식 파악
- `ir/templates/`에 .pptx가 있으면 `python ir/scripts/format_profile.py <파일>` 실행.
- 기존 IR이 PDF뿐이면 `render` 없이 페이지 이미지를 보고 색·폰트·여백·로고 위치를 수동으로 `format-profile.md`에 기록.
- 서식이 없으면 `tokens.json` + `pro-deck-builder` 원칙을 쓴다.

## 4. 레퍼런스 서칭
- **먼저 `refs/ir/portfolio/`(사용자 작업 IR 26건)와 `refs/ir/samples/`(수집 상장사 IR 21건)를 같은 비중으로 본다.** 업종·단계가 비슷한 덱 2–3개를 골라 구성, 레이아웃, 차트 방식을 우리 기준으로 삼는다. (고객 정보가 담긴 자료이므로 내용·수치를 다른 덱에 옮기지 않는다)
- 조사서의 업종·단계·톤으로 검색어 3–5개를 만들어 웹 검색 (예: "<업종> series A pitch deck", "<업종> IR 자료 공개", "YC demo day deck <카테고리>").
- 우선 출처: 회사가 직접 공개한 덱, 공시(DART) 자료, 공개 아카이브. 유료·로그인 필요 자료는 건너뛴다.
- `refs/ir/<작업명>.md`에 기록:
  | 회사·덱 | 링크 | 단계 | 구조(슬라이드 순서) | 참고할 점 | 따라 하지 말 것 |
- 마지막에 "우리 덱에 가져올 것 3가지"를 요약.
- **저작권**: 남의 덱 이미지·파일을 저장하지 않는다. 링크, 요약, 구조 분석만. 문구를 길게 인용하지 않는다.

## 5. 스토리 구성
- 스킬: `investor-pitch-deck` (슬라이드별로 증명할 것), `deck-narrative-arc`, `deck-outline-first`, `chart-choice`
- 먼저 슬라이드 제목만으로 이야기가 읽히는지 확인 (제목 = 결론 문장, "매출 현황" X → "2년 만에 매출 6배")
- 기본 구조 (단계에 맞게 조정): 표지 → 문제 → 해결 → 제품 → 시장 → 비즈니스 모델 → 성과(트랙션) → 경쟁 → 성장 전략 → 팀 → 재무 계획 → 투자 요청 → 마무리
- `ir/deck.json` 작성 (형식은 `ir/deck.sample.json` 참고). 숫자는 직접 쓰지 말고 `value_ref`나 `chart.data`로 data 파일을 가리킨다.

## 6. 생성·렌더
- `python ir/scripts/build_deck.py ir/deck.json`
- `python ir/scripts/render.py output/ir-<작업명>/deck.pptx`

## 7. 검수 (하나라도 실패면 고치고 다시 렌더)
| 항목 | 기준 |
|---|---|
| 숫자 | `check_numbers.py` 통과: 덱의 모든 숫자가 data에 있음 |
| 메시지 | 슬라이드당 메시지 1개, 제목이 결론 문장 |
| 가독성 | 본문 18pt 이상, 한 슬라이드 40단어 안팎, 한글 줄바꿈 어색함 없음 |
| 차트 | 단위·기준일·출처 표기, 강조는 한 군데만 |
| 서식 | format-profile(또는 tokens.json)의 색·폰트만 사용 |
| 시각 | `preview/*.png`를 직접 보고 넘침·겹침·잘림 없음 |
| 일관성 | `ib-check-deck`, `deck-review-rubric` 점검 |

결과는 `output/ir-<작업명>/review.md`에 저장.
