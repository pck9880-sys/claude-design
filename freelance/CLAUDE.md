# 외주 작업 규칙 — Claude와 Codex 공통

이 폴더의 설정·기록은 외주 작업용이다. 사용자 지시가 우선한다. 한국어로 안내한다.

## 시작
1. 이 파일, `HANDOFF.md`, 해당 프로젝트의 `STATUS.md`와 `brief.md`를 읽는다.
2. Git 브랜치·상태를 확인한다. 다른 환경의 변경이 있으면 먼저 동기화하며, 사용자 미커밋 변경은 보존한다.
3. 루트의 기존 템플릿 brief가 비어 있더라도, 이 폴더의 프로젝트별 확정 요구사항과 사용자 지시가 실제 작업 기준이다. 범위 밖 내용을 추측하지 않는다.
4. 고객별 입력·출력은 `projects/<고객명>/` 안에 저장한다. 공통 환경 수정은 `scripts/`, `docs/`, `templates/` 안에서 한다.

## 실제 편집
- 요청한 앱으로 편집 가능한 원본을 만든다. InDesign은 INDD와 IDML, Illustrator는 AI, Photoshop은 레이어가 있는 PSD를 기본으로 한다. 형식 이름만 바꾸거나 평면 이미지를 붙여 원본이라고 부르지 않는다.
- 기존 디자인은 기준본 사본에서 요청 페이지·요소만 수정한다. PPTX를 Adobe 원본으로 옮기는 것은 별도 제작이며 자동 변환만으로 동일한 편집 품질을 보장하지 않는다.
- PC Adobe 실행을 확인하지 못한 클라우드에서는 기획·스크립트·지시서 준비 상태로 명시한다. 코드 작성만으로 앱 실행·출력·검수가 완료됐다고 보고하지 않는다.
- 지원되는 Adobe 연결 도구가 있으면 실제 기능과 입력 요구사항을 확인하고 사용한다. 이 대화의 Adobe 연결이 Claude에서도 된다고 가정하지 않는다. 확인하지 않은 MCP 서버·키·계정을 만들지 않는다.
- 새 고객 데이터를 지어내지 않는다. 프로젝트 모먼트 수치는 저장소 루트의 `ir/data-project-moment/`가 기준이다. 레퍼런스의 고객 내용·숫자를 재사용하지 않는다.
- Pretendard 및 저장소의 승인된 폰트를 사용한다. 인쇄 출력은 판형·도련·색상·ICC·링크·라이선스 확인 후 정한다. 미확정 상태에서 인쇄용 완성이라고 보고하지 않는다.

## 디자인 품질
- 레퍼런스를 읽었다고만 하지 말고 실제 페이지를 열어 여백·타이포·이미지 점유·차트 위계를 비교한다. `docs/REFERENCES.md` 양식을 따른다.
- 페이지별 원문·수치·목표/실적 구분을 유지한다. 그래프가 브랜드 이미지보다 과하게 커지지 않게 구성 목적을 검토한다. 같은 비율 설명을 여러 곳에 반복하지 않는다.
- 결과를 실제 Adobe 또는 지원 렌더러에서 출력해 수정 전후를 비교한다. 글자 잘림·겹침·왜곡·폰트 대체·링크 누락을 확인한다.
- 파일 검증만으로 디자인 합격을 선언하지 않는다. 실제 확인하지 못한 부분은 `HANDOFF.md`에 남긴다.

## 저장·이어하기
- 버전별 파일 + 작은 PDF 미리보기 + 변경 설명을 함께 저장한다.
- Git LFS가 필요한 환경에서는 `git lfs pull`을 실행해 실제 원본이 있는지 확인한다. 포인터 파일을 Adobe로 열지 않는다.
- 시작·종료마다 프로젝트 상태와 공통 `HANDOFF.md`를 갱신한다. 다음 실행자가 바로 쓸 첫 지시문을 남긴다.
- 현재 신규 작업은 `projects/2026_11.16_인생사진첩/`이다. InDesign 메인·Illustrator 보조, 개인 PC가 꺼져도 서버에서 실행하는 것이 요구사항이다. 프로젝트 STATUS.md와 가능성 조사 기록을 읽고, 계정·서버·실제 실행이 미확인인 상태를 완료로 보고하지 않는다. 모먼트 디자인은 별도 요청 없이 변경하지 않는다.
