# Adobe 출력 확인 — v002

2026-11-16

- 직접 작성한 24p IDML을 Adobe 저장소에 업로드하고 InDesign 렌더링 연결 도구를 호출했다.
- 최초에는 INVALID_ARGUMENT/Job failed 응답. 이후 패키지 선언·기본 리소스·객체 참조·순서를 보완하자 렌더링 성공 응답과 PDF/JPEG 링크가 반환됐다.
- **실제 JPEG를 열어 확인한 결과 페이지가 흰 화면이었다.** 파일 처리 성공을 본문 출력 성공으로 인정하지 않았다.
- 표준 기본값·참조·페이지 객체 순서와 위치를 바꾸어 확인했으나 이 세션에서 원인을 해결하지 못했다. 이 결과만으로 사용자 데스크톱 InDesign 또는 Adobe 서비스가 잘못됐다고 판단하지 않는다.
- 사용 불가 IDML 및 빈 PDF/JPEG는 GitHub의 납품/편집 원본으로 배포하지 않는다. 로컬 `work/` 진단 자료는 Git 제외.
- 24페이지 디자인 좌표와 자체 SVG 검토도는 보존하고, Adobe 앱의 기본 문서·페이지·텍스트·사진 프레임 API를 쓰는 `BuildLayoutV002.jsx`로 편집 원본을 생성하도록 준비했다. 이는 아직 실제 PC 앱에서 실행하지 않았다.
- `BuildLayoutV002.jsx`는 24페이지 전체를 만들고 실제 파일을 버전별로 저장하며, 본문/사진 레이어·문단 스타일·자산 라벨·오버셋 보고·원본 보존을 포함한다.
- API 목록 비활성화 화면과 별개로 이 대화의 Adobe 연결 도구는 렌더링 요청을 처리했다. 따라서 향후 연결 도구의 지원 기능을 개별 확인해야 하며, 직접 API·상시 서버 이용 권한이 생겼다고 가정하지 않는다.
