# Adobe 제작 환경

## 현재 전제

사용자 PC에 InDesign·Illustrator·Photoshop이 설치·로그인되어 있다. 클라우드 작업 세션은 해당 PC에 연결되어 있지 않으며, 여기서 앱 실행을 검증하지 않았다. 앱 자동화가 필요하면 PC의 로컬 Claude Code/Codex에서 실행한다. 이 폴더에는 임의의 Adobe MCP 서버나 자격 증명을 추가하지 않았다.

## 앱 선택과 편집 가능한 원본

| 앱 | 역할 | 저장·검토 |
|---|---|---|
| InDesign | IR·제안서·다페이지 인쇄/디지털 레이아웃 | 버전별 INDD + IDML + 링크 이미지, 검토용 PDF |
| Illustrator | 원형/막대 차트·다이어그램·벡터 일러스트·단일 페이지 | 편집 가능한 AI, PDF 호환 저장, 검토용 PDF/SVG |
| Photoshop | 제품 사진·누끼·보정·합성 | 레이어 유지 PSD, 배치용 PNG/TIFF/JPEG |

원본이 PPTX인 모먼트는 전체를 InDesign으로 재제작할지, AI/PSD 자산만 만들고 PPTX에 배치할지 결정한 뒤 작업한다. 파일 확장자 변경이나 PDF 변환만으로 편집 품질을 보장하지 않는다.

## PC에서 최초 점검

1. `scripts/check-adobe.ps1`로 설치 항목과 CLI 경로를 진단한다. 계정 비밀번호·로그인 토큰은 수집하지 않는다.
2. Photoshop: 파일 → 스크립트 → 찾아보기에서 `scripts/adobe/probe.jsx` 실행.
3. Illustrator: 파일 → 스크립트 → 기타 스크립트에서 같은 파일 실행.
4. InDesign: 창 → 유틸리티 → 스크립트의 사용자 폴더를 탐색기로 열어 `probe.jsx` 사본을 넣고 패널에서 실행.
5. 각 앱의 이름·버전 알림을 확인해 프로젝트 핸드오프에 기록한다. 이 점검은 문서를 수정하지 않는다. 메뉴 이름은 버전·언어에 따라 다를 수 있다.

JSX는 Adobe 앱 내부에서 실행하는 코드다. 휴대폰이나 Node에서 실행하지 않는다. 새 제작 스크립트는 요청 범위와 입력/출력 경로를 확인해 작성하고 실제 앱 실행 후 검수한다. 실행하지 못하면 `PC 실행 필요`로 남긴다. 스크립트 실행 여부만으로 디자인 품질이 확보되지는 않는다.

## 실제 작업 순서

1. Git 동기화, LFS 원본 내려받기. 원고·기준본·수정 페이지 확인.
2. 레퍼런스 실제 화면과 비교 기준 기록.
3. `source/`에 새 버전 사본 생성. 원본과 고객 폴더는 덮어쓰지 않음.
4. InDesign 링크는 `links/`에 유지하고 missing/modified 링크, 오버셋 텍스트·누락 폰트를 점검. 공유 시 Package 사용, 폰트 배포는 라이선스에 따름.
5. Illustrator는 데이터·텍스트·벡터 객체를 편집 가능하게 유지. Photoshop은 레이어를 유지하며 배치 이미지는 별도 출력.
6. 검토용 PDF/이미지를 `output/`에 저장해 수정 페이지와 전후 비교. 최종 인쇄 출력은 도련·ICC·PDF 규격을 고객 사양에 맞춰 점검.
7. 변경점·검증 수준·다음 할 일을 기록하고 원본·출력을 Git/LFS로 저장.

## 이 대화에서 제공되는 Adobe 연결 기능

- InDesign: PDF→INDD/IDML 변환, INDD/IDML 렌더링, 템플릿 데이터 병합.
- Illustrator: AI 파일 렌더링/출력, 템플릿 데이터 병합, 이미지 벡터화.
- 이미지: 지원되는 보정·선택·배경 작업 등.
- 이런 기능은 PC 데스크톱 앱의 임의 레이어·오브젝트를 원격으로 조작하는 연결과는 다르다. 각 도구가 지원하는 작업에만 사용한다.
- 도구가 필요한 파일은 Adobe가 접근 가능한 업로드 자산/URL이어야 한다. GitHub 비공개 파일 경로를 그대로 전달해 접근할 수 있다고 가정하지 않는다.
- Claude에서는 해당 계정에서 사용 가능한 연결을 별도 확인한다. Codex/ChatGPT의 연결이 자동 공유되지 않는다.

## 큰 파일

`freelance/.gitattributes`는 이 폴더 아래의 AI/PSD/PSB/INDD/TIFF 원본에 LFS를 적용한다. 기존 저장소의 큰 PPTX 이력을 변경하지 않는다. 고객별 저장공간·전송 한도는 계정에서 확인하며, LFS가 없거나 한도 오류가 나면 완료로 보고하지 않는다. IDML·PDF가 100MB 이상이면 별도로 LFS 적용 후 저장한다.
